# Контракт `fact` 1.0.0: запись реестра

**Пишет:** база (`cm_kb`), расчетчик (записи `CALC`), ядро (записи `ASM` из журнала допущений).
**Читает:** верстка (идентификатор у каждого показателя, `sources[].label` в подвал, `status` для подсветки `check`), картограф (`fact_ids` у объектов геопакета), расчетчик (входы).

## Что зафиксировано

- Четыре вида записей с разными префиксами: `F-NNNNNN` факт, `CALC-NNNNN` расчет, `NORM-NNNNN` норма, `ASM-NNNN` допущение. Номера сквозные внутри проекта, не переиспользуются.
- У любой записи минимум один источник с готовой подписью `label`. Подпись пишет база, верстка ее не сочиняет и не сокращает.
- Значение хранится как в источнике; формат показа (пробелы в тысячах, запятая) — дело верстки.
- Статус `check` обязателен для всего, что не сверено с источником. Верстка показывает `check` акцентным цветом и справочной строкой в отчете, не ошибкой.
- `conflict` — когда документы расходятся; обе записи ссылаются друг на друга через `conflicts_with`, верстка показывает оба значения с источниками.
- У `CALC` обязательны входы и формула; смена входа обязывает расчетчик пересчитать запись.

## Что запрещено

- Запись без источника. Для допущений источник — журнал допущений.
- Подпись источника без документа (`label` вида «по данным консорциума»).
- Проектные константы в коде модулей: все значения — записи реестра.

## confirm — подтверждает база в первом докладе

1. Префикс факта: в паспорте верстки записано `F-NNNNNN` как согласованное; в пилоте верстки использовано `FACT-TBD-NNN`. Здесь зафиксировано `F-NNNNNN`. База подтверждает или называет текущий формат своего реестра.
2. Префикс нормы `NORM-NNNNN` — предложение; база называет свой, если уже есть.
3. Набор `doc_status` и соответствие классам A–J.
4. Поле `applicability` у норм: словами или структурой — как в реестре базы.
