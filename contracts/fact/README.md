# Контракт `fact` 1.1.0: запись реестра

**Пишет:** база (`cm_kb`), расчетчик (записи `CALC`), ядро (записи `ASM` из журнала допущений).
**Читает:** верстка (идентификатор у каждого показателя, `sources[].label` в подвал, `status` для подсветки `check`), картограф (`fact_ids` у объектов геопакета), расчетчик (входы).

## Что зафиксировано

- Четыре вида записей с разными префиксами: `F-NNNNNN` факт, `CALC-NNNNN` расчет, `NRM-NNNNN` норма, `ASM-NNNN` допущение. Номера сквозные внутри проекта, не переиспользуются. Префикс `NORM-` из 1.0.0 устаревает: схема его принимает, пока `slide`, `image`, `overlay` и `geopackage` не перейдут на `NRM-`; убрать в 2.0.0.
- У любой записи минимум один источник с готовой подписью `label`. Подпись пишет база, верстка ее не сочиняет и не сокращает.
- Значение хранится как в источнике; формат показа (пробелы в тысячах, запятая) — дело верстки.
- Статус `check` обязателен для всего, что не сверено с источником. Верстка показывает `check` акцентным цветом и справочной строкой в отчете, не ошибкой.
- `conflict` — когда документы расходятся; обе записи ссылаются друг на друга через `conflicts_with`, верстка показывает оба значения с источниками.
- У `CALC` обязательны входы и формула; смена входа обязывает расчетчик пересчитать запись.
- У `NRM` обязательна `applicability` — объект: `condition` (условия словами, как в документе), `status` (`unchecked`, `applicable`, `not_applicable`), необязательные `exceptions`, `note`, `checked_by`, `checked_at`. `status` записи говорит о сверке значения с документом, `applicability.status` — о применимости к объекту проекта: верно процитированная норма может быть неприменима.
- `doc_status` источника: `approved` утвержден, `draft` проект или рабочий, `superseded` устарел, `unknown` неизвестен, `external` чужой документ, `reference` справочный источник.

## Что запрещено

- Запись без источника. Для допущений источник — журнал допущений.
- Подпись источника без документа (`label` вида «по данным консорциума»).
- Проектные константы в коде модулей: все значения — записи реестра.

## Подтверждено базой (ответы Романа, 11.10.2026)

1. Факт — `F-NNNNNN`, совпадает с реестром базы.
2. Норма — `NRM-NNNNN`, как в реестре базы.
3. `doc_status`: утвержден → `approved`; проект, рабочий → `draft`; устарел → `superseded`; неизвестно → `unknown`. Классы A–J совпадают.
4. `applicability` — объект, поля по реестру норм базы.

## confirm — читатели подтверждают в первом докладе

1. Верстка: `norm_id` в `slide` и шаблон идентификатора в `image` — на `NRM-NNNNN`.
2. Картограф: шаблон идентификатора в `geopackage` — на `NRM-NNNNN` (`overlay` — сделано в 1.2.0).

## Изменения

1.0.0 — 11.10.2026 — первый черновик.
1.1.0 — 11.10.2026 — префикс нормы `NRM-`, `doc_status` с `superseded` и `unknown`, `applicability` объектом; база по ответам Романа.
