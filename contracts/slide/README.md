# Контракт `slide`: описание слайда

**Владелец схемы:** верстка. Действующая схема — `cm-design/schema/slide.schema.json`. Верстальщик кладет сюда копию `schema.json` с номером версии и `example.yaml` из пилота (слайд с таблицей, числом и картинкой) при первом же коммите в этот репозиторий; дальше копия обновляется при каждой смене версии.

**Пишет:** агент-верстальщик в ядре (навык `slides`), база (`check_slides` читает идентификаторы), позже рецепты.
**Читает:** `cm-deck build`, `lint`.

## Что зафиксировано (из паспорта верстки, раздел 10, и решений Д1–Д2)

- У каждого показателя — идентификатор по контракту `fact`: `{cells, fact_id}` на строку таблицы, `{text, fact_id}` на ячейку, `{text, fact_ids}` на числа в тексте. Линтер верстки: отсутствие идентификатора — ошибка (C01).
- `status: check` допустим у строки и ячейки; верстка подсвечивает.
- `analog: true` обязателен для материалов аналогов; верстка пишет пометку сама.
- `source_label` показателя выводится в подвал после источников слайда (Д-040).
- Картинки — по контракту `image`.
- Верстка факты не проверяет; это делает база по идентификаторам до сборки.

## Что запрещено

- Числа в тексте без идентификатора.
- Подписи источников, набранные вручную в описании слайда, если показатель имеет идентификатор: подпись берется из реестра.
