# Контракт `geopackage` 1.0.0: геопакет проекта

**Владелец:** картограф. **Пишет:** картограф (`ingest`, `fetch`, `analysis`). **Читает:** база (объекты и их `fact_ids`, статусы), расчетчик (геометрия для буферов и подсчетов), верстка (не читает напрямую — получает карты по контракту `image`).

Схема описывает содержимое одного файла `.gpkg`: перечень слоев, геометрию и обязательные поля объектов. Файл проверяется скриптом картографа при каждой сборке; `example.json` — выгрузка такого файла в JSON для теста.

## Что зафиксировано

- Один файл — одна система координат, из `project.yaml`. Пересчет внешних источников при импорте.
- Перечень слоев закрытый. Новый слой — новая версия контракта. Пустые слои допустимы.
- У каждого объекта: устойчивый `object_id` вида `слой:ключ`, `kind` словами, статус геометрии, готовая подпись источника, дата источника.
- Пять статусов: `official`, `cadastral`, `digitized`, `concept`, `reference`. Статус повышается только документом. Для `digitized` обязательно, откуда и когда оцифровано.
- `fact_ids` связывает объект с реестром базы: площадь по ТЭП — факт, а не измерение по контуру.
- Атрибуты слоя — в `attrs`, имена полей латиницей, без проектных значений в именах.

## Словари `kind` по слоям

Ведутся в `kinds.yaml` рядом (появится с этапом 1 картографа). Пока: `sites` — участок ППТ; `concept_sites` — участок концепции; `blocks` — квартал; `zouit` — ЗОУИТ по видам (СЗЗ, охранная зона, водоохранная, приаэродромная); `poi_*` — по типам учреждений.

## Что запрещено

- Объект без статуса или источника.
- Слои с данными, запрещенными к печати по лицензии (Яндекс, 2ГИС, Google).
- Правка геометрии руками в QGIS с сохранением в выпускной геопакет: только через `ingest` и правила.
- Хранить в геопакете персональные данные из ЕГРН (правообладателей): только кадастровый номер, границы, вид использования.
