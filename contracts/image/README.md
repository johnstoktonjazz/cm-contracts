# Контракт `image` 1.0.0: картинка с описанием происхождения

**Пишет:** картограф (карты, схемы по данным), генератор схем верстки (схемы из описания), база (картинки из документов: планы, виды), автор проекта (фото).
**Читает:** верстка: ставит картинку в место макета, строит подпись, легенду и источники из этого файла, а не из описания слайда.

## Что зафиксировано

- Рядом с каждой картинкой лежит `<имя>.provenance.json`. Картинка без него в сборку не попадает (ошибка линтера).
- Карты и схемы приходят точно под размер места макета (`size_mm`) и не масштабируются верстка (Д-006); размеры мест — из `layout-matrix.yaml` верстки, картограф их читает оттуда.
- Легенда карты — отдельным файлом в натуральную величину; верстка ставит ее низом по низу рамки карты (Д-040).
- Тип картинки (`kind`) и статус геометрии (`status`) — обязательны и видны в подписи: рендер не выдается за фото, оцифрованное со слайда — за официальное (принцип 11).
- У карты обязательны система координат, масштаб и список слоев с источником каждого. Внешние слои (OSM, НСПД, реестры) — `reference`, с лицензией в `source`.
- `fact_ids` связывает картинку с записями реестра: что она показывает.

## Что запрещено

- Подложки и слои, которые нельзя печатать по лицензии (Яндекс, 2ГИС, Google) — не попадают в `layers` карт для альбома.
- Текст, впечатанный в картинку, вместо подписи в описании (кроме подписей на самой карте).
- Картинка `placeholder` в сдаваемом альбоме.

## confirm

1. Поля `size_mm`, `legend_file`, `source`, `date`, `point` — верстальщик сверяет с `image.yaml` и `map.yaml` и называет расхождения.
2. Имена статусов геометрии — картограф подтверждает при написании контракта `geopackage`; должны совпадать.
